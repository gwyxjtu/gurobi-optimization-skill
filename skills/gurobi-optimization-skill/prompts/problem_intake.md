# Step 1: 问题理解 (Problem Intake)

## 目标
准确理解用户的优化问题，收集建模所需的全部信息。

## 执行流程

### 1.1 收集问题信息
向用户确认以下要素（缺失时必须追问）：

| 要素 | 问题 | 示例 |
| :--- | :--- | :--- |
| **优化目标** | 要最大化/最小化什么？ | 最小化总成本、最大化利润 |
| **决策变量** | 需要做哪些决定？ | 生产量、运输量、是否选中 |
| **约束条件** | 有哪些限制？ | 产能上限、需求必须满足 |
| **输入数据** | 数据在哪里？格式？ | CSV文件、Excel、手动输入 |
| **问题规模** | 大致有多少变量/约束？ | 100个变量、50个约束 |
| **求解要求** | 时间限制？精度要求？ | 60秒内、gap < 1% |

### 1.2 问题分类
根据收集的信息，判断问题类型：

```
决策变量是否连续？
├── 是 → 目标/约束是否线性？
│       ├── 是 → LP（线性规划）
│       └── 否 → 是否二次？→ QP/QCQP/SOCP
└── 否（含整数/二元变量）→ MILP/MIQP
```

### 1.3 输出
生成 **问题定义卡**：

```markdown
## 问题定义卡
- **问题名称**: {名称}
- **问题类型**: {LP/MILP/QP/...}
- **优化目标**: {最大化/最小化} {目标描述}
- **决策变量**: {变量列表及含义}
- **约束条件**: {约束列表}
- **输入数据**: {数据来源及格式}
- **规模估计**: {变量数} × {约束数}
- **求解要求**: {时间/精度}
```

将问题定义卡写入 `outputs/{问题名}/problem_definition.md`。

## 注意事项
- 如果用户描述模糊，必须追问，不要假设
- 区分"硬约束"（必须满足）和"软约束"（尽量满足）
- 确认数据的单位和量纲一致性

## ⛔ 数据来源规则（强制）

**所有业务数据必须来自用户，Agent 禁止编造。**

1. 用户描述了问题但**没给数据**时：
   - 列出"建模还需要以下数据清单"
   - 要求用户提供 Excel/CSV/JSON 或直接在对话中给出数值
   - 不得继续 Step 2（数据分析），直到数据就绪

2. 用户说**"先用示例数据"**时：
   - 代码中必须用 `# ⚠️ 示例数据，需替换为实际数据` 注释标注
   - 交付时必须提醒用户："以下数据为占位示例，请替换为实际数据后再运行"
   - 示例数据必须标注来源（如"Gurobi 官方案例"、"用户要求的占位值"）

3. 数据验证（使用 `tools/data_validator.py`）：
   ```
   python3 tools/data_validator.py --data user_data.csv --required "字段1,字段2,字段3"
   ```
   验证通过后才能进入 Step 3（数学建模）
