# 迭代意图识别与上下文加载

## 目标
识别用户是否要在已有模型基础上进行修改，而非从头建模。

## 识别信号
以下任一条件成立时，进入迭代模式：

1. 对话中已出现 `outputs/{问题名}/model.py` 路径
2. 用户提到"修改模型"、"调整约束"、"换目标函数"、"加个变量"
3. 用户引用了上一轮的求解结果
4. 用户提供了已有模型代码文件

## 迭代类型判断

| 用户意图 | 迭代类型 | 处理文件 |
|---------|---------|---------|
| 调整参数（目标权重、容量上限等） | 参数调整 | `parameter_tuning.md` |
| 添加/删除变量或约束 | 结构修改 | `model_revision.md` |
| 切换目标函数 | 结构修改 | `model_revision.md` |
| 修复求解错误 | Bug 修复 | 直接修改代码 |
| 对结果不满意，想优化方向 | 重新建模 | 回到 Step 1 |

## 输出规范
1. 新代码另存为 `outputs/{问题名}/model_{YYYYMMDDHHmmss}.py`
2. 追加 `outputs/{问题名}/optimization_iteration_log.md`
3. 迭代记录格式：

```markdown
## {时间} - 迭代 #{N}

### 变更内容
- 修改了什么
- 为什么修改

### 影响分析
- 目标函数变化: {旧值} → {新值}
- 求解时间变化: {旧时间} → {新时间}
- 可行性: {保持/改善/恶化}

### 代码差异
- 新增变量: ...
- 新增约束: ...
- 修改参数: ...
```
